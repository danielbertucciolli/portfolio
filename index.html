Sem build, sem drama.

Daniel BertuccioliFull stack developerTexto de exemplo
Neste artigo Por que sem build O setup inteiro Quando deixa de valer Regra prática

Muitos projetos de cliente têm uma página, um formulário e meia dúzia de interações. Para isso, instalar um bundler, um transpilador e centenas de dependências cria mais manutenção do que valor.

Por que sem build

Um arquivo HTML abre em qualquer lugar. Você pode enviar por e-mail, hospedar em qualquer servidor estático e entregar ao cliente sem explicar como rodar o projeto.

  • Entrega rápida, sem etapa de instalação.
  • Menos dependências para atualizar ou quebrar.
  • Qualquer pessoa da equipe abre o arquivo e entende o que acontece.

O setup inteiro

Tailwind pelo CDN cuida do estilo e JavaScript puro cuida do comportamento. Este é o esqueleto de uma página.

index.html
<!-- estilo: um único script -->
<script src="https://cdn.tailwindcss.com"></script>

<button id="enviar" class="rounded-lg bg-red-600 px-4 py-2 font-bold">
  Enviar
</button>

<script>
  const botao = document.getElementById("enviar");
  botao.addEventListener("click", () => {
    botao.textContent = "Enviado";
  });
</script>
DicaComece com tudo em um arquivo. Quando ele passar de umas 600 linhas, separe o CSS e o JavaScript em arquivos próprios, ainda sem build.

Quando deixa de valer

O script do CDN foi pensado para prototipar e para páginas pequenas. Em um produto com muitas telas, equipe grande e testes automatizados, um build traz ganhos reais: arquivos menores, verificação de tipos e CSS gerado só com o que você usa.

Escolha a ferramenta pelo tamanho do problema, e não pelo tamanho do currículo.Regra de bolso

Regra prática

Se o projeto cabe na cabeça de uma pessoa e entra em produção em dias, fique sem build. Se precisa de várias pessoas trabalhando ao mesmo tempo, migre. A troca é simples quando o código já está organizado.

Todos os blocos do blog e do currículo, prontos para copiar. Cada exemplo abaixo mostra o componente e o HTML dele. As cores e fontes vêm das variáveis do início do arquivo.

Como usar

Em quatro passos

  1. Copie o <style> e o bloco de símbolos SVG do início do arquivo.
  2. Troque as variáveis em :root ou escolha uma paleta com data-palette para mudar cor e fonte do site inteiro.
  3. Copie os componentes abaixo com o botão "Copiar HTML".
  4. Reaproveite as vistas: cada <main data-view> é uma página.
